# OTA 市场页 V2

基线 main `e91e9ca`。本轮仅修改 OTA 市场展示和相关测试，不修改 API、Schema、采集、策略规则或生产配置。

## 真实数据口径

- 总览来自所选入住日期、市场范围的最新快照。已采集数量为 API 返回的酒店观察记录数，不代表全城酒店总量；PARTIAL 明确保留。
- 有效价格为当前列表有限、非负的数值 `display_price`，真实零价计入。覆盖率 = 有价记录 / 列表记录；均价为这些价格的算术均值。无快照展示缺失；无有效价格均价缺失；空列表覆盖率缺失，不除零。
- 中位数和最低/最高价继续使用不可变 `snapshot.facts`，不混用其他日期、范围或酒店分类。搜索/分类仅影响列表，不改变总览、趋势和策略。
- 趋势按独立入住日期显示 T～T+14 / T～T+30 共 15/31 点。保留缺口；相邻已观察点沿用既有绘图方式，不生成缺失日期价格。Tooltip 加入有价样本、真实采集状态和时间；假期沿用仓库已确认的 2026 日历，未知年份明确未确认。
- 酒店行保留平台排名、起售价，并展示原价、评分、原始动态和活动。房型从已有 `rooms` 按 platform + hotel_id 精确匹配；缺少房型不解释为售罄。折叠详情展示原始平台名称、ID 和房型观察，不混用其他快照。
- 市场变化仅展示 API 已计算的同市场、同入住/退房日期、同范围历史比较事实 `comparable/up/down/medianChange`。现有 market-v1 涨跌阈值为 ±3%，旧价 ≤0 或任一缺价不计入可比样本；前端不重算规则。可比样本为零时不显示误导的涨跌零值。

## 未实现的变化功能

现有 API 返回各入住日期最新快照和策略历史，并未提供前一快照的酒店观察集合、前后快照配对 ID/时间或逐酒店涨跌。因此不实现新出现、暂时缺失、逐酒店价格差，也不把相邻入住日期或 PARTIAL 的遗漏当作酒店消失。

后续建议：只读接口在严格相同市场/入住退房/范围下返回前后快照 ID、采集时间、采集状态和原始观察集合；用 platform + hotel_id 比较，仅两端有效价格计算差值。新增/未观察必须结合采集完整性表达为“本次新增观察/本次未观察”，不推断开业、停业或售罄。需要独立产品和 API 审查；本轮不增加接口或数据库迁移。

## 页面与验证范围

桌面保留经营分析结构，首屏紧凑总览，表格限定高度并固定表头。手机总览使用两列、原指标横向浏览、趋势和表格内部滚动，避免固定列遮挡详情入口；名称列提供真实平台起售价摘要；不把所有卡片纵向堆叠。

自动测试使用隔离固定数据；Chromium 检查使用明确的合成 fixture，不写生产数据。自动页面检查不等于真实 Chrome/Mac/Windows 或生产验收。Cloudflare 构建与部署仅在 Git Integration 中验证，Codex 不直接部署。
